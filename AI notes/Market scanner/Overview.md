# Market scanner

A native program that drives the game's Market, Auction House and currency exchange with synthetic input and reads them off the screen, to replace loa-buddy as the site's price source (loa-buddy stays the fallback) and to collect what nobody offers (accessories, gems). It writes SQLite and uploads each pass to the site's Worker (`Frontend/External services.md`, "Market scanner passes"); the site's prices are the newer of each material's lowest listing here and loa-buddy's price (`/prices`, `Frontend/External services.md`). Two regions, each pass scanning both in turn: NAE on the character Kenicards (Thaemine) and EUC on Kenimommy (Arcturus), each parked in its Stronghold: the windows are translucent, so a steady background behind them keeps crop matches repeatable, and the hourly chaos-gate notice does not show there. What was tried and failed is in `Overview tried.md`.

Code: `crates/market` (`hf-market`), Windows only. Text is read by PP-OCRv5 through rten (`pp.rs`); the model is not tracked: `rec.onnx` and `dict.txt` from Hugging Face `monkt/paddleocr-onnx` (`languages/english`) go in `ignored/market/models/en_PP-OCRv5_mobile_rec/` before building. Running on other PCs through a relay and Discord: `Remote.md`.

## Files and the portable layout

- `assets.rs`: the templates (`refs/`, `names/`, `gems/`, `items/`), both recognisers' models and the digit font are built into every exe (about 20 MB). Each template folder is overridden file by file from the profile folder (a file's key is its name without `@x_y` and extension): the crate's own folders by default, so a crop saved by `ref` works without a rebuild; `profile/` beside the exe in the portable layout.
- Logs, the database, `debug/`, `strips/`, `upload.json` and the relay configs live in the data folder: `ignored/market/` by default, `data/` beside the exe in the portable layout (`market_agent` without `--dev`).

## Running

- `cargo run --release -p hf-market --bin market_scan -- [--gap 60] [--once] [--quick] [--strips] [--only materials,gems,accessories,exchange] [--regions NAE,EUC] [--db PATH]`: a pass of each region (one upload each), then waits `--gap` minutes after it ends, again, until F10 is held or Ctrl+C. F10 stops at the next action and still stores and uploads what the pass read (`run.rs`).
- `pnpm market-agent` (`market_agent --dev`): the same passes, a round at every multiple of the gap (default 2 hours, UTC) with the game closed in between, started and paused through the relay or its console (`Remote.md`). Started and stopped by hand; it launches the game when needed; the game must be logged in through Steam, full screen at 1920x1080 on the primary layout, and the PC is not usable meanwhile (the game is kept in front). Writes `ignored/market/market.sqlite`, logs to `ignored/market/scan.log`, keeps screenshots of what it could not read in `ignored/market/debug/`.
- `pnpm market-scan [--gap N] [--once] [--strips]` is the usual run: materials, gems and the currency exchange. Accessories are paused (2026-11-20) until wanted again; their code, values and crops are kept and `market_scan` run directly (cargo, above) still runs them by default or with `--only accessories`.
- A pass takes about 7 min of materials, 1.5 of gems, 10 s of currency exchange and 8 min of accessories. `--quick` runs every path in a few minutes: 2 rows of each materials page, gems at levels 10 and 5, two level pairs per accessory group.
- `--strips` keeps every crop that is read, with what was read and the item or search it belongs to, in `ignored/market/strips/<time>/` (`index.jsonl`; about 1,900 crops and 4 MB a pass) (`strips.rs`). `python crates/market/tools/verify_strips.py [folder]` (onnxruntime, numpy, pillow) reads them again with PP-OCRv5 in Python and draws every disagreement with both reads into `disagree_<n>.png` for checking by eye. For numbers that is an independent second reader; text is read by PP-OCRv5 already, so there it only checks the Rust port. `pp_eval <folder>` prints the Rust reads of a folder's text crops.
- `--upload-only` sends the passes not sent yet and exits. Uploading needs `ignored/market/upload.json` (`{"url": "<Worker>", "token": "<MARKET_TOKEN>"}`); without it nothing is sent.
- `market_ctl "<commands>"`: drive and read by hand; the command language is in `ctl.rs` (click, scroll, key, type, shot, `ocr`, `num`, `ref`, `looks`).
- `game_capture` (`pnpm game-capture`): stills and debug captures of the game for the inventory scanner, not the market (`Screen scanner/Live game.md`).
- `market_mcp`: the same as an MCP server (`lostark-market` in `.mcp.json`; tools `screenshot` and `run`). `--remote <machine>` drives a machine's agent through the relay instead (`lostark-home` = this PC; `Remote.md`). Build first: it runs `target/release/market_mcp.exe`. Each Claude Code session starts its own copy and holds the exe, so only a build that relinks `market_mcp` needs them closed (`/mcp` to disable it); `--bin market_scan` builds don't.
- `input_test`: which ways of sending input the game takes (below). `glyph_eval`: scores the number reader on `ignored/market/dataset/labels.json` (102 labelled numbers over every number style; 102 right); `glyph_eval <strips folders>` reads their number crops again and prints every read that changed, to check a change to the reader against real passes. `cap_dump`: frames of an `.hfcap` as PNGs.
- Never build while `market_scan` runs: Windows locks the exe. Use `CARGO_TARGET_DIR=<scratch>`.

## Input and capture

- Plain `SendInput` works, not elevated (2026-11-20): absolute moves land on the exact pixel, clicks with or without delays, and keys as virtual keys, scan codes or unicode characters. `LOSTARK.exe` is not elevated. Text is typed as unicode (case and spaces kept, which the search boxes need). Should injected input ever be refused, the fallback is a USB HID device (Pi Pico) fed over serial.
- Every action first brings the game to the front (`Game::focus`, AttachThreadInput then SetForegroundWindow) and stops if F10 is held or `game::STOP` is set: it unwinds with the panic payload `Stopped`, caught by the pass (which keeps what it read: sections fill a vector item by item, a failed section's items are dropped) and by the binary. Screenshots are GDI captures of the game's monitor (`xcap`); full screen works.
- All coordinates are 1080p client pixels, measured on this machine; nothing scales.

## Getting around

- **Alt+Y toggles the Market and always opens it fresh**: Market tab, Search Market, class = own class, All Tiers, category tree collapsed. Market sections and the first search of a list start from that (`fresh_market`; Esc if Alt+Y does not open it, the game menu may be up).
- **Steps wait for the screen, not a fixed time** (`ui::wait`, `ui::act`): after a click the screen is polled every 0.25 s until it shows what the step should bring (a title, a crop, the next page number), up to a few seconds (10 for windows, 60 for the shop's first open); a click that is harmless to repeat is repeated when its result does not come. `act` also takes a delay before each try, for screens that show before they take clicks. Lists and windows whose contents come after their title still get a short fixed settle.
- **Units of work are tried again from a reset UI** (`ui::unit`; a unit that failed every try is sent as an error event with its last screenshot, `report.rs`): a Market section (all its pages), each gem or accessory search, the currency exchange. When one fails it keeps a screenshot in `ignored/market/debug/`, closes the Market and the shop (`ui::reset`), waits 5, 20, then 60 s and runs again from the start; after four failures it is left out of the pass (not stored as empty). Every failed try that has another after it also goes out as an `error` event (R2 `shots/` and Discord, text `unit: try k/4 failed (last log line)`, 2026-11-22), and the screenshot is the screen at the step that failed: steps that give up call `ui::fail` (logs the reason and keeps the screen before any cleanup key), else the screenshot is taken after the unit returns. Reads that degrade without failing a unit (5-day hover, `steady`) are only logged and kept in `debug/`, not sent. Meant for network jitter anywhere in the UI (on 2026-11-21 the Market list once did not open and a whole section was lost). Not handled yet: a lost connection (reconnect prompt, log-in or server screens); recovering from it belongs in `ui::reset`, to be investigated.
- **State is checked by reference crops, not text** (`refs/<name>@x_y.png`, max-channel grey, optionally with alpha: transparent pixels are not compared, for a translucent element whose background changes; `in_stronghold` keeps the 34% of its pixels that agree within 15 between two Strongholds, 2026-11-22; `looks` = mean difference under 14 at the best of five 1 px shifts; a match reads 0.0, one row off reads 32). Window titles, headers, the Buy button, picked dropdown values, typed option keywords. A new one is made with `market_ctl "ref name x y w h"` once the screen shows the right thing.
- **Dropdowns are picked and checked, and picked again when the check fails** (`pick`): the first pick after Alt+Y often does not take. Lists that scroll are scrolled to the top first and then down a known number of rows (one notch is one row, 29 px).
- **Switching region** (`region.rs`, between the regions of a pass; with one region the logged-in character is used as is): Esc (game menu), Char. Select (1204, 750), its OK (906, 584), character select (about 25 s, `char_select` = the Launch button), Server (80, 1010), the region's tab (EUC 705 / NAE 874, 517) and the "Change Region Server" prompt's OK (918, 593), the server row (first row of both; clicked 15 px below where `server_<region>` was taken), Enter (958, 923; `act` waits 3 s before each click: the server and tab crops match within 0.5 s of the region prompt's OK, but Enter ignored every click until about 3.5 s), roster page 1 (190, 1015), the character's slot (y 922, x 108 right of where `char_<region>` was taken, so another PC's characters need only their crops; it matches only when picked, blue: 0.5 against 28), Launch (852, 1012), until the Stronghold's Exit/Teleport/Guide icons show (`in_stronghold`, about 30 s; the same in both Strongholds). The first log-in after 06:00 server time opens an attendance window over the Stronghold (every day on the scanner accounts); the wait also takes `attendance` (the "Login Events" tab, text pixels only, under 5 not 14: bright sand read 20.2, the three kept popups 0.0 to 0.1) and Esc closes it, so it costs no retry (2026-11-23; borry-laptop's first EUC log-in of the day read 0.03, before the fix shipped). In-game "Switch Servers" lists only the current region's servers. A failed switch is tried again as a unit; it picks up from character or server select. A switch that fails every try panics the round (`run::round`), so the agent restarts the game at once instead of switching the next region from the same screen; `market_scan` stops there. The game's "Cannot connect to the server. [EAC Offline]" on Launch is a non-descript error (not only the network) and is to be expected now and then: it drops to server select with the Event Notice window, where Esc opens "Exit Game" instead of the game menu, and only a restart clears it (borry-laptop 2026-11-24). Each character needs F9 bound to the shop (keybinds are per character). EUC's Auction House is thin for high gems (2026-11-21: one Lv. 10 Doomfire, no Lv. 10 Blazing, five Lv. 9 Doomfire, checked by hand), so short gem lists there are real.
- **The hourly notice** (chaos gate, 3 min before and on the hour) covers the window's top elsewhere but not in the Stronghold, so nothing waits for it.
- **Something covering a value** (log-in messages, now turned off in the game; a table still drawing in): a value that does not parse is read again from a new screenshot after 2.5 s, up to four times (`steady`). Kept as a sanity check.
- **The shop** (F9; the first open can take a while, waited for up to 60 s by its title crop): Currency Exchange (1636, 1036) is pressed only on the shop's page and Leave (1814, 1036, closes the shop from either page) only while a shop title shows; Buy (bottom left) and the exchange's purchase panel (bottom right) are never touched. The mouse waits at (1900, 600): the bottom bar's currencies have tooltips that reach the tables. The tables draw in for a moment after the title, so the first read waits 1.5 s.
- **A fresh Market lists by lowest price**, which reorders while pages are read; each list is sorted by Rank (a fixed order) by clicking its header until `rank_sorted` (the header's gold top edge) matches.
- **Never buy**: the Market's Buy (1580, 926) is pressed only when the Market header and the Buy button both match their crops (the Auction House's Bid/Buy sits on the same spot), and only to open the purchase window, which is closed by its X. Enter is only pressed in the Auction House search box.

## Reading

- **Numbers are read by the game's font, not the recogniser** (`glyph.rs`): split at empty columns, a glyph under half the line's height is a separator ('.') or dash when it sits within the digits' height, else ignored (a "Competitive" tag's edge in the corner of an Auction House bid read as '-' and failed the search), every other is compared with each digit drawn in `public/fonts/English.ttf` (ExuberanceF) with `ab_glyph`, sized to the line's digit height (5 sizes ±6%), at quarter-pixel offsets and ±1 px, against the crop scaled between its background and its brightest ink. The best has to beat the next digit by 1.25x, else '?'. Colour and size of the text do not matter (white, gold, blue, yellow-green; table, window, tooltip). Separators are told by the column: `parse_number` knows which columns have one decimal.
- **Items are told first by their name block in the purchase window** (`names/<name without ':'>.png`, the icon and both lines, 795..1090 x 205..255; the 32 honing items), compared over ink pixels only (`ink_distance`, the window is translucent): the same item reads 0.0, the closest two items (Tremor [12-15] and [16-19]) 4.6. Accept under 2.5 and 2 clear of the next.
- **Else by their icon** (`icons.rs`): the game's own art for every item that can be listed in the material categories (`items/`, written by `python crates/market/tools/market_items.py` from `scanner_setup/game_files`; run it again after a game update), drawn 46 px square at (802, 205), compared by normalised cross-correlation over the art's opaque pixels (so the rarity background does not count), at ±1 px. Great Destiny Leapstone scores 0.976, the next icon 0.864. Icons over 0.9 and within 0.03 of the best are kept, and when they are several items the name read decides: the numerals must be the item's, and a name the window cuts short ("Destiny Crystallized") is compared with as much of each as was read. All 65 items of a pass were named right, the 33 trade skill items without crops. An item none of this names is kept in `ignored/market/unknown_names/` with its read.
- **The name block** is the name's lines and perhaps "[Sold in bundles of N units]", which gives the bundle; a wrapped name's second line ("[19-20]") is not a bundle.
- **Gem rows likewise** by `gems/<Lv. N Kind Gem>.png` (the name text of a row, 612..762); every row's nearest crop must be the gem searched.
- **Text is read by PP-OCRv5 mobile English** (`pp.rs`, rten 0.26 loads the `.onnx`): grey, cut to the largest run of ink columns (a table's divider is not text), padded 4, stretched, inverted, 48 px high, CTC. It writes no spaces, so names are compared without them. It read every purchase-window name and every time left of a pass, where ocrs had read "Taorig:Hefr1921" and "52m" for "20h52m".
- **The 5-day hover's rows are found by their coins**: a "-" day's row is 26 px against 28, so the rows below one sit higher.

## What a pass reads

- **Materials**: Enhancement Material > All at Tier 4 (the 32 honing items) and Trade Skill > All at all tiers (33), every page ("1/4" under the list, read by the font; the '/' reads as a digit, so the first and last digit are taken, right up to 9 pages); each item keeps its category. Each row: Buy opens the purchase window: avg day price, recent price, available quantity, and the price tiers (four shown, a notch down shows the fifth; the list holds five, which sum to the available quantity). Hovering the avg day price shows "Average price for the last 5 days", today first. An item with no trades today ("-") has no hover. 65 items in about 7 min.
- **Gems**: Auction House, class All, the search box with "Lv. N Doomfire Gem" (damage) / "Lv. N Blazing Gem" (cooldown), N from 10 to 5, Enter; the first page (10), sorted by buy-now. T4 is Doomfire and Blazing; Annihilation and Crimson Flame are T3.
- **Accessories**: Advanced Search, Reset, then category, class All, Ancient, Tier 4 and two "Refinement Bonus" rows with an option each, min = max at one level. Groups: necklace dps (Additional Damage, Outgoing Damage Increase), necklace support (Brand Power, Increased Serenade/Piety/Harmony Meter Gain), earrings dps (Atk. Power %, Weapon Power %), ring dps (Crit Rate, Crit Damage), ring support (Ally Atk. Power Enhancement Effect, Ally Damage Enhancement Effect); support earrings have nothing of interest. Level pairs high/high, mid/mid, high/mid, mid/high, high/low, low/high: 30 searches. The values (low/mid/high) are what the min/max lists offer for Ancient T4, in `GROUPS`. A group's settings stay between searches; only the levels change, after a check of the rest.
- **Currency exchange**: F9, Currency Exchange, its Information page (empty rows are skipped, not the end: with under five Royal Crystal offers the blanks are at the top, 2026-11-22): "Royal Crystal Sale Offers" (5 lowest; gold per 100 Royal Crystals, quantity), "Crystal Purchase Offers" (5 highest; gold per 100 Crystals, quantity) and "Recent Prices" (7; price, gold sold, crystals sold), all by the font ('.' is the shop's thousands separator). The History page is one's own transactions only.
- **Search results** are taken when they differ from the search before (a search that did not go through leaves the old rows), when buy-now ascends (else the header is clicked), and nothing only after four empty reads 2.5 s apart (two let a slow answer through as empty on borry-laptop twice on 2026-11-24, its rows showing up in the next search, which then failed as the wrong gem).

## Upload

- After each pass, `upload::payload` builds one JSON: `{version, region, machine, started, finished, sections, points}` (`machine`: the agent's relay name, else the computer's name, lower case; since 2026-11-22). A stopped pass is uploaded with what it read; one that read nothing is not. `sections` holds everything read, by kind (`material`, `gem`, `accessory`, `exchange`), as the structs serialise (keys in alphabetical order); each material, search and exchange read carries `at`, when it was read (UTC to the second, `upload::stamp`; also the `at` column of `materials` and `searches`). Passes stored before 2026-11-21 had `at` set to their `finished` afterwards, in D1 and in the local payloads; a new kind of data is a new section, and the Worker does not look inside. `points` are `[key, day, value]` for the daily history: `material/<name>/avg` (the 5-day hover), `material/<name>/lowest` and `/recent`, `gem/Lv. N <kind>/lowest`, `accessory/<item> <category> <a>/<b>/lowest` (the lowest buy-now), `exchange/royal_sale/lowest`, `exchange/crystal_purchase/highest`, `exchange/recent/latest`; the scan's own values are dated the scan's UTC day.
- **The 5-day averages are of complete days, not a rolling 24 h**: all five (and the Avg. Day Price, the first of them) stayed the same in every read from 05:49 to 17:39 UTC on 2026-11-20 while recent prices moved (Great Destiny Leapstone 80, 40, 58, 53). Against the third-party API's daily averages they fit with the first being 2026-11-19 (UTC) and fit worse one day either way, so the first is dated the day before the scan (UTC). Neither the tooltip ("Average price for the last 5 days", five values) nor the column header shows dates. The day rolls over at 00:00 UTC (not the 10:00 UTC reset): on 2026-11-21 an item read at 23:59:58 still had the old five, one at 00:00:13 had them shifted by a day, and every item had shifted by the next pass. That PC's clock is UK time, the same as UTC in November, so it may be local midnight instead; assumed UTC until a run on another time zone tells.
- The payload is kept in `scans.payload` and sent after the pass; `scans.uploaded` marks it sent. A failed send is retried after the next pass (`send_pending`, oldest first). A pass sent twice is stored once.

## Storage

`db.rs`: `scans` (one per pass, with its upload payload and whether it was sent), `materials` (name, raw name, bundle, avg day, recent, available, category), `depth` (tier 0-4, price, quantity), `history` (days ago 0-4, avg), `searches` (kind gem/accessory, item, category, gem level, level a/b, result count) and `listings` (rank, name, trades, quality, time left, min bid, buy now). The currency exchange is only in the payload.

## Open

- The site reading more of the uploads: prices other than the lowest listing (a toggle on the market page). Gems are shown (the market page's Gems tab, lowest buy-now only).
- Accessory listings record the two options searched, not the third option (it is only on the hover tooltip).
- Recovering from a lost connection: the reset between tries only closes the scanner's own windows (`ui::reset`).
- Other resolutions are not handled.
